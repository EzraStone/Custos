§ 01

Nobody can list the agents they are already running

Companies are running autonomous agents that hold credentials, call tools, and write to production systems without a human reading each action. They were not procured. They were built by a team that needed one, given a role, and deployed.

Identity systems decide which agents may authenticate. Nobody decides which actions are permitted — and at most companies, nobody can say which agents are running at all.

Every tool in this category is opt-in. Your coverage equals the list you already had, and the list you already had is the problem.

Eval and tracing platforms instrument agents someone chose to instrument. Runtime AI security blocks attacks against agents someone chose to protect. Tenant registries see agents inside the tenant, not the ones running as an IAM role in a VPC. Each of those is useful. None of them answers the first question a security lead actually has.

§ 02

See, attribute, stop

Three capabilities in a strict dependency order, and the order runs one way. Enforcement without discovery governs an empty register — it can only reach the agents that were already known, reviewed, and least likely to be the problem. Discovery without enforcement is a report read once and filed.

01 —

See

Find the agents running in a cloud account, including the ones nobody enrolled, from network and identity metadata alone. No host agent, no sidecar, no SDK to adopt, no code change in any workload.

Built · running end to end
02 —

Attribute

Resolve each finding to its owner, its credential, and what that credential permits. A finding nobody can route is noise, and noise gets the tool uninstalled.

Built · running end to end
03 —

Stop

Gate consequential actions against deterministic policy the customer authored, with a signed receipt for every decision — allow, deny, or hold for a human.

Not started, deliberately
Why the third one is empty

The Checkpoint is not started until a paying customer asks for it by name. It is the half that is worth more, and it is also the half that is unsellable until the register it governs has something in it. Building it first would mean asking a customer to enumerate their agents — which is the exact thing they cannot do.

§ 04

How an agent separates from a chatbot

Both make TLS calls to the same model endpoints. Payloads are encrypted and, by invariant, never inspected. So the classifier gets metadata and nothing else — and everything downstream depended on one untested claim:

An agent is distinguishable from a chatbot backend using network and identity metadata alone.

That claim is now tested against an adversarial corpus, at both flow log aggregation intervals, with the negatives built specifically to defeat the obvious signals.

G0 PASS

Separation margin +0.26. Full recall, zero false positives, identical at 60-second and 600-second aggregation.

The signal that carries it is cumulative egress-to-ingress asymmetry against model endpoints. An agent resends its entire accumulated transcript on every step, so over an episode of n steps its bytes sent grow as n² while bytes received grow as n. A chatbot sends one prompt and receives one answer, and both grow linearly.

It is a property of summed bytes, which is why aggregation cannot touch it — and why the result is identical whether a customer's flow logs are configured at 60 seconds or at the cheaper 600.

The finding that mattered most was a negative

The specification's headline signal — bursts of sequential model calls with sub-second gaps — is not implementable. Flow logs aggregate per 5-tuple over a fixed interval, every provider SDK pools connections for around ninety seconds, and so twenty sequential model calls collapse into one record with the timing gone. Measured on the busiest agent in the corpus: fewer than 0.5 flow records per model call.

Two further signals the specification expected to carry the classifier were measured and rejected, with the numbers that killed them recorded in the source.

§ 05

What never leaves the account

Prompts, completions, and payload bodies, under any configuration. Not as a redaction step — a redaction step is a filter, filters have bugs and configuration, and a reviewer is right not to trust one.

There is simply no field on any wire type capable of holding a payload, and the shipper's only entry point accepts nothing but those types. Two files establish the entire privacy claim, and both are open source.

SEC-16
Discovery is read-only. Enforced in the IAM policy and in code. TestNoMutatingAPIs
SEC-17
Discovered records confer no authority. One function can sanction, and it needs a human. test_sec17_*
SEC-18
Metadata only. Enforced by wire types having no field that can hold a payload. TestWireTypesCarryNoPayload
SEC-19
The collector is inert without an explicit destination. TestZeroConfigIsInert
SEC-20
A finding without an owner is segregated, never mixed into owned findings. test_sec20_unattributed_segregated

Each invariant names the test that enforces it. They are written so that breaking one requires deliberately editing a test named after the thing you are breaking.

§ 06

Built, and not built

Stated plainly, because a security product that overstates once is never trusted again.

collector Go binary, read-only role, flow logs from CloudWatch or S3, principal resolution, IAM enumeration, ALB access logs. Apache-2.0. Built
classifier Five weighted signals, each with a sentence a human can argue with. Weights fitted on the A0 corpus. Built
register Agent records with provenance, owner, reach, and blast radius read from IAM policy. Built
report The delivered artifact. Owned findings, review band, unattributed candidates, and a stated limitations section. Built
checkpoint Inline enforcement gateway. Not started until a paying customer asks for it. Not started
console Operator UI. The report is the product until someone needs to click something. Not started
real capture Every number here comes from synthetic telemetry. No scan has run against a real account. Pending a design partner
SOC 2 Type I evidence collection needs three months of observation. It gates enterprise contracts, not pilots. Not yet

Not being built

Multi-tenancy, RBAC and SSO before a paying customer. Policy authoring UI. Machine-learned classification before three design partners have produced real traffic. Kubernetes pod-level attribution, which needs eBPF or audit logs and is more invasive than the cross-account role the whole entry motion is built to avoid. And internet-wide scanning, which is not possible without a privileged vantage point and inherits the entire civil-liberties objection the in-account model avoids.

§ 07

What we are asking for

An AWS account and a read-only role

The technical risk that justified building first is resolved. Every remaining question is answerable only by pointing this at an environment nobody here has seen: whether the byte ratios hold against real provider endpoints, whether tag hygiene is good enough that attribution resolves, and how many workload shapes exist that the corpus does not anticipate.

Onboarding is one Terraform apply against a non-production account, targeted at thirty minutes and no meeting. You can read every line of the collector first, and you can run it in dry-run mode against your own account to see the literal bytes before granting it anywhere to send them.
